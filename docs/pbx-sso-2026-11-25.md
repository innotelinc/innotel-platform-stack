# FreePBX administration now signs in with Cerulean Authentik — 2026-11-25

The FreePBX 17 administration GUI no longer asks for a FreePBX password on any
public name. A request on the edge is authenticated by Authentik, and the identity
Authentik establishes is what FreePBX uses. The local password form still exists
on the container's own port for break-glass, and nowhere else.

## Why it was not working before

Two faults, either of which alone would have shown the password form:

1. `voice.innotel.site` forwarded to `192.168.1.52:8201`, a port nothing has ever
   listened on. The Authentik gate passed, and the post-login request died
   upstream. Fixed first (now `:8083`, the FreePBX Apache).
2. The gate authenticated but never passed the identity. NPM writes
   `advanced_config` at **server** level, and its generated `location /` sets its
   own `proxy_set_header` lines, so nginx does not inherit the server-level
   `X-authentik-*` headers into the location. FreePBX's SSO shim therefore saw
   no user at all and fell through to its login form. This affected every host
   using the managed gate, not just the PBX.

## What FreePBX does now

`/var/www/html/admin/libraries/gui_auth.php` (in the `freepbx-www` volume) reads
the identity the edge forwarded and opens the GUI without a password:

- A username in `sso_identities.php`'s `users` map, or a member of a group in its
  `groups` map, is opened as that FreePBX account. The maps currently resolve
  `dhunter` and every member of `authentik Admins` (`akadmin`, `dhunter`, `admin`)
  to the FreePBX `admin` account.
- A request that arrives **from the edge** with no identity, or with one that maps
  to nothing, gets a 403 page that names Authentik and the group to ask for. It
  does **not** get the password form — that would be a second door that skips the
  identity provider and its MFA.
- A request that arrives on the container's own address is untouched: the local
  form is the break-glass door when Authentik is unavailable. All the SSO code
  only runs when `REMOTE_ADDR` is the NPM edge (`192.168.1.71`).

Backups from this change: `gui_auth.php.bak-sso-edge-20261125` beside the file
(the earlier 11-22 attempt's backups are still there too).

## Edge changes

Every FreePBX GUI name now carries a `location /admin` block in its NPM advanced
config, with the identity headers set **inside** the location (server level is
silently dropped, see above):

| NPM host | name | backend |
| --- | --- | --- |
| 388 | `voice.innotel.site` | `http://192.168.1.52:8083` |
| 165 | `voice.innotel.us` | `http://192.168.1.52:8083` |
| 399 | `pbx.telno.services` | `http://192.168.1.52:8083` |
| 405 | `pbx.it.com`, `www.pbx.it.com` | `http://192.168.1.52:8083` |
| 404 | `fax.telno.services` | `http://192.168.1.52:8083` (AvantFAX under `/fax/`) |

Also gated in the same pass, because they were open:

- 403 `voice.telno.services` → `https://192.168.1.52:8089` (Asterisk ARI) had no
  gate at all; now Authentik in front.
- 410 `pbx.innotel.site` → `http://192.168.1.52:8097` served the Asterisk Console
  to anonymous requests; now Authentik in front.
- 387 `voice.capstone.innotel.site` was already gated.

Unauthenticated requests to all eight now `302` to the Authentik outpost of their
zone. A client that sends `X-Authentik-Username` itself gets the gate's `302`,
because the gate overwrites those headers from the outpost response.

## Verified

- A temporary Authentik user (created, used, deleted) signed in through the real
  flow at `auth.innotel.us`, then loaded
  `https://voice.innotel.site/admin/config.php`: **200**, FreePBX GUI, no
  password form, final URL the config page.
- The same identity before it was added to `authentik Admins`: **403** from the
  shim, no form.
- From the edge address with no identity: **403**. With a forged header from
  outside: **302** to Authentik.
- Direct `http://192.168.1.52:8083/admin/config.php` from the LAN: **200** with
  the local form (break-glass intact).
- `nginx -t` on the edge: successful.
- `voice.innotel.us` reaches its provider's authorize page (that provider uses an
  explicit consent flow, so the automated probe stops there; the GUI block is the
  same as the verified host).

## Operating notes

- **Adding a PBX administrator**: put the person in the `authentik Admins` group
  in Authentik. No FreePBX change is needed, and nothing in `gui_auth.php`
  changes. To give one person access without the group, add
  `'their-username' => 'admin'` to `sso_identities.php`.
- **If a FreePBX framework update overwrites `gui_auth.php`**, the password form
  comes back on the edge. The marker that the SSO block is present is the string
  `Sign-in is managed by Cerulean Authentik`; the file is otherwise the stock
  login path. Keep the volume, not just the container.
- **Do not move `location /admin` back to server level** in the NPM advanced
  config; nginx will ignore the headers.
- `voice.innotel.us` continues to use its own `Voice NPM Forward Auth` provider;
  the others use their zone's provider. Both set the same user headers.
