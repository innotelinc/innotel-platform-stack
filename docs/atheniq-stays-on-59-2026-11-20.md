# AthenIQ stays on `.59` (2026-11-20)

**Decision: the estate keeps serving AthenIQ from `atheniq` (`.59`). The parallel
stack on `.120` is not a replacement, and no cutover is planned.** The move had been
planned, rehearsed as far as a filled search index, and was scrapped on 2026-11-20
before any public name moved.

## What serves the public names

| Name | Upstream |
|---|---|
| `atheniq.courses` | `192.168.1.59:18080` |
| `catalog.atheniq.courses` | `192.168.1.59:18080` |
| `learn.atheniq.courses` | `192.168.1.59:18080` |
| `apps.atheniq.courses` | `192.168.1.59:18080` |

`.59` runs Tutor 22.0.2 on `docker.io/overhangio/openedx:22.0.2-indigo` with
`ENABLE_HTTPS: true` on `18080`/`18081` behind the edge, and it owns the mail relay,
the Cerulean OIDC client, the shared session cookie domain and the theme that the
public names depend on. None of that moves.

## What was scrapped

- the parallel-stack bring-up (`scripts/atheniq-parallel-stack.sh`) and the
  image-migration helper (`scripts/atheniq-migrate-to-image.sh`) — both deleted;
- the cutover decision note and the two-tutor-root config diff — both deleted, their
  still-true findings folded into this file;
- the plan to build the institute platform on `next.atheniq.courses` and flip DNS.

`atheniq-next` (`.120`) is still running and still answers `next.atheniq.courses`
through the edge. It is a lab box: nothing production-facing points at it, and
nothing in this repository now treats it as a target. Removing it is a separate
decision, and its data was never authoritative.

## What has to stay true on `.59`

1. **The `atheniq_search` plugin keeps `SEARCH_MAX_PAGE_SIZE = 250`.** The catalog
   asks for the whole catalogue in one page (120), `edx-search` caps at 100, and the
   yml hand-edit is regenerated by `tutor config save`. The plugin is what makes it
   durable — `atheniq-cutover-and-migration-2026-11-18.md` §1.
2. **`TUTOR_ROOT=/home/tutor/.local/share/tutor`.** A bare `tutor` run as root
   targets `/root/.local/share/tutor` and changes nothing the containers read (§2 of
   the same file).
3. **`check-edge-front-door.py` keeps failing when a public name answers from a
   container instead of the edge.** It was written while `.120` was being rehearsed
   and it is a plain front-door check now: the names above must resolve to the edge.

## If this is ever revisited

It needs a reason that is not "a newer image exists" — the fork image is built in CI
(`.github/workflows/build-openedx.yml`, branch `atheniq/verawood`) and runs on `.120`
today. Reopening the move would still need a freeze-and-restore of Mongo, MySQL and
the media volume, the mail relay and OIDC client carried across, and `18080` or its
edge equivalent on the far side. None of that work is undone; it is simply not
scheduled.
